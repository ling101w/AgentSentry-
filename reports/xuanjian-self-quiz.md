## B. 参考答案

1. **三个核心问题**：① 用户是否明确授权了这个能力和具体目标；② 当前参数是否实际使用了低可信或敏感数据；③ 这个动作是否越过确定性的安全边界。对应"谁授权、数据从哪来、要流到哪去"。

2. **本质区别**：关键词过滤是"回答过滤"，在文本层面工作；玄鉴是"行为监督"，拦截点在工具真实副作用落地之前，判断依据是授权边界、数据来源、污点流向和副作用形成的证据链，而不是字符串匹配。位置更接近风险落地点。

3. **提示词不够的原因**：间接提示注入会让恶意指令经由网页/邮件/工具返回进入上下文，模型意图被污染后，提示词无法保证每一次工具调用仍在用户授权范围内。所以要在模型和工具之间建运行时监督层，把工具调用当作需审计的安全事件。

4. **三种裁决**：`allow`（放行）、`ask`（不放行，必须人工审批）、`deny`（执行前阻断）。`ask` 表示动作尚未执行，处于挂起审批态。

5. **主链路**：OpenClaw lifecycle hook → normalize action → TaskSpec V2 capability 授权 → 字段级 provenance/taint graph → 确定性策略执行 →（仅歧义时）semantic judge（1–2s 预算 + 缓存）→ allow/ask/deny → apply effects + 异步审计。

6. **四域一环**：上下文溯源（污染入口）、状态完整性（持久化状态/记忆）、意图授权（任务漂移）、工具边界（工具落地副作用）；证据回流环把工具结果、审批状态、运行时审计和风险向量回写会话，动态收紧后续决策。

7. **三者分工**：Authorization Graph 把最新用户请求解析成显式 capability set（路径、origin、method、收件人、命令、有效期）；Provenance/Taint Graph 记录 tool-result 字段如何流入后续 tool 参数，只在污染真实到达 sink 时阻断；Deterministic Enforcement 执行 URL origin/SSRF、canonical path、敏感文件、持久化、Memory Guard、工具完整性等硬边界，不依赖模型可用性。

8. **Judge 硬约束**：① 只处理确定性规则无法判断的语义歧义；② 只能收紧、不能放宽确定性裁决；③ 有 1–2 秒延迟预算和缓存；④ 使用独立环境变量 `AGENTSENTRY_API_KEY`，不复用业务 key；⑤ 未配置 key / 网络不可用 / 超时都不会关闭确定性策略。

9. **effects 契约**：`evaluate(snapshot, action, config)` 在克隆的 snapshot 上计算，返回 `{decision, effects}`，不修改调用方会话状态；最终裁决后才由 `applyEffects` 统一提交状态并异步写审计。好处是评估无副作用、可重入、可测试，状态提交是单点的。

10. **TaskSpec V2**：capability 只能从用户最新请求解析授予；**模型可以建议 capability，但不能授予 capability**。约束维度：文件路径、网络 origin、HTTP method、邮件收件人、命令和有效期。它把"模型想做什么"和"用户允许做什么"分开。

11. **避免一刀切**：做的是字段级 provenance——追踪具体哪个 tool-result 字段进入了哪个后续参数，只有污染数据真实到达 sink（敏感读取、外发、命令、记忆写入等）才触发数据流阻断，而不是按"会话被污染"整体判死。

12. **总结毒网页可被允许**：外部内容被标为低信任标签后，可以参与摘要、可以展示给用户，只是不能驱动高风险动作。后续若试图读敏感路径或外发，taint-to-sink 检查在执行前拒绝。这就是"可总结不可外发"的细粒度策略，也是低误拦的来源。

13. **Memory Guard**：独立 256-bit Memory Guard key；HMAC timing-safe 校验（记忆护照：来源、信任等级、内容哈希、上下文哈希、风险向量、完整性签名）；namespace 与来源约束；写入前检查 + 读取时重新校验可信度。拒绝保护键修改、审批绕过、默认外发、低信任来源写入权威未来行为的记忆。

14. **SSRF/URL 防护五层**：exact 与 prefix 规则分离；origin 校验含端口；DNS 解析后检查私网/metadata IP；逐跳重定向验证；流式大小限制。

15. **恶意 Skill 阻断**：时机是技能安装/落地之前（执行前）。依据是增量 provenance scan + Tool Security Manifest + digest pinning，比对"能力声明 vs 实际行为"；语义动作图发现"本地配置读取 + 外部发送"的危险组合结构即阻断，未知工具进审批。与样例关键词无关，所以改名、换说法仍会命中。

16. **红队场景（举例）**：① 外部内容注入（邮件/网页/PDF/图片元数据藏指令）→ trust label + taint-to-sink；② 记忆与配置持久化投毒 → 记忆护照 + 写入来源检查；③ 工具调用劫持（MCP 投毒、网关覆盖、恶意技能）→ manifest 扫描 + 非本机网关识别；④ 系统命令与高影响工具 → 执行前确定性裁决 + 审计，不真实落地。

17. **隐藏邮件三动作**：读邮件 → allow（进审计，内容标低信任）；读本机密钥 → deny（任务越界 + 敏感路径）；发外部归档邮箱 → deny（低信任上下文驱动高风险外部发送，收件人不在授权内）。

18. **核心数字**：共 840 条 = 综合攻击回归 520 + 工具攻击专项 320；攻击/期望保护 711 条，正常/期望放行 129 条；保护率 100%、正常放行率 100%、高风险漏放 0、误拦 0。

19. **全量 vs 分层 Judge**：全量 Judge 同样 0 漏放但正常样例误拦 7 条、总耗时约 135.2 分钟；风险分层后误拦降为 0、总耗时约 76.8 分钟。结论：语义裁判适合用在敏感路径和高风险工具上做复核，不应对低风险请求无差别调用——确定性策略当硬边界，Judge 当高风险复核器。

20. **开关对比**：8 个隐蔽攻击场景（隐藏邮件、恶意网页、PDF 透明文本、图片元数据、历史回放、长期记忆污染、网关劫持、恶意技能）。未开启时危险动作释放 8/8，阻断率 0%；开启后释放 0/8，阻断或审批率 100%。

21. **不能宣称绝对安全**：① 840 条是公开内容映射后的开发回归，不是独立盲测；② 不是 AgentDojo/InjecAgent 原生端到端成绩（native adapter 已实现但模型驱动发布结果保持 `not_run`）；③ 只证明当前测试覆盖内规则边界稳定，不能证明未知攻击泛化能力；④ 真实部署还需业务白名单、审批缓存、行为画像持续积累。

22. **标签隔离**：历史标签不进入 detector 输入；新评测协议把 labels 保留在 evaluator-owned envelope 中。重要性：防止评测变成"带着答案考试"，保证拦截依据来自运行时证据而非先验标签，结果才有可信度。

23. **四 profile**：`observe`（只记录告警，无阻断基线）、`balanced`（approval，日常，高风险进审批）、`competition`（approval，比赛演示，启用 provenance judge、写 root、响应覆盖）、`high-security`（block，强约束，要求内核 observer）。

24. **Dashboard 安全**：默认只绑 loopback；bootstrap token 认证，裸访问返回 401；token 写入 HttpOnly + SameSite=Strict session cookie 后立即从地址栏移除；Host/Origin 校验；绑 0.0.0.0 必须显式启用远程访问并配置 token。

25. **能力边界（任意 3 条）**：① eBPF observer 的 `connect` 只记录 pid/comm/fd，不解析目标地址，网络目的地控制靠应用层 preflight + 部署侧 egress allowlist；② canonical path 检查存在 check/use 时间窗，更强隔离需要 `openat`/`O_NOFOLLOW`/检查过的 fd；③ 行为检测是轻量在线统计基线（tool × task-class 的 warm-up、TTL、滑动窗口），不是 IsolationForest/GNN 等训练模型；④ `src/agentsentry/` 是早期离线原型，不是比赛主链。

26. **两条链关系**：`src/agentsentry/`（FastAPI + SQLite，8000 端口）是早期离线原型和辅助研究接口，用于单元测试和复现实验；`openclaw-plugin/`（8765 Dashboard）才是比赛主链和生产系统。

27. **答辩思路（区别）**：内容安全网关/Guardrails 工作在文本输入输出层；玄鉴工作在工具执行前的行为层，裁决依据是授权图 + 污点图 + 确定性边界的证据链，且 Judge 只能收紧不能放宽。可以承认互补关系：它们管"说什么"，玄鉴管"做什么"。

28. **答辩思路（过拟合）**：① 防线是结构化的（语义动作图抽取行为组合结构，不依赖固定字段/关键词）；② 标签隔离协议；③ 留了诚实声明（非盲测、native adapter not_run）；④ 开启/关闭对比证明因果有效性；⑤ 后续方向是独立盲测 + 原生端到端。承认边界反而加分。

29. **答辩思路（Judge 被注入）**：Judge 是纵深防御里的"复核器"而非单点：① 它只能收紧不能放宽，被注入最坏情况是误拦（fail-closed），不会放宽出安全事故；② 确定性硬边界不依赖 Judge 可用性，Judge 挂了/超时策略照常；③ 独立 key、延迟预算、缓存降低攻击面；④ 输入给 Judge 的内容本身是带 trust label 的。
